## Why

Проект шутера не имеет автоматизированных тестов. Это затрудняет рефакторинг, усложняет поиск regressions и не позволяет уверенно добавлять новый функционал. Модульные тесты позволят проверять отдельные компоненты изолированно, обеспечивая стабильность при развитии проекта.

## What Changes

- Добавление фреймворка Google Test через CMake `FetchContent` (автоматическое скачивание и сборка)
- Реорганизация `CMakeLists.txt` для поддержки сборки тестов (выделение библиотеки `shooter_lib` из основного проекта)
- Создание директории `tests/` с тестовыми файлами
- Написание модульных тестов для ключевых компонентов: `GameState`, `GameObjects`, `Fabric`, `Map`, `CObject`, `EventHandler`

## Capabilities

### New Capabilities

- `testing/unit-testing`: Инфраструктура модульного тестирования — интеграция Google Test, конфигурация CMake, структура тестов и набор тестовых сценариев для основных компонентов

## Impact

- **CMakeLists.txt**: реорганизация — выделение объектов в статическую библиотеку `shooter_lib`, добавление `FetchContent` для Google Test, создание цели `tests`
- **Структура директорий**: новая директория `tests/` с поддиректориями по аналогии с `src/`
- **Зависимости**: добавление Google Test (скачивается автоматически при первом запуске CMake)
- **Сборка**: основной исполняемый файл `run` продолжает собираться через `make`; тесты собираются через `cmake --build build --target tests`
