## Context

См. `proposal.md` — Why. Генератор `LevelGenerator` создаёт уровень в `generateLevel()` в порядке: `generateGround` → `generatePlatforms` → `generateTrees` → `generateItems` → `generateEnemies`. Платформы — это объекты `GroundBlock`, добавляемые в общий вектор `std::vector<GeneratedObject> objects` в порядке создания (стартовый блок первым). Деревья добавляются в тот же вектор как объекты `type == "Tree"` с координатой `y`, равной верхней грани блока, и `x` внутри границ блока.

Ограничение проекта (`AGENTS.md`): цикломатическая сложность каждой функции НЕ ДОЛЖНА превышать 2. Поэтому логику необходимо декомпозировать на маленькие функции с не более чем одной ветвью.

## Goals / Non-Goals

**Goals:**
- Детерминированно размещать `Ammunition` на каждой третьей платформе, `Heart` — на каждой четвёртой и `Crystal` — на каждой второй.
- Пропускать платформу, если на ней есть `Tree`.
- Убрать случайное размещение `Crystal`, `Ammunition` и `Heart` — размещение предметов становится полностью детерминированным.
- Уложиться в цикломатическую сложность ≤ 2 на функцию.

**Non-Goals:**
- Новые типы объектов (кристалл — это существующий `Crystal`).
- Изменение формата уровней, `Map`, `GameObjects`, `Fabric` и интерфейсов объектов.
- Изменение логики расстановки деревьев, врагов, земли.

## Decisions

### Где размещать логику
Новый публичный метод `generatePlatformItems(std::vector<GeneratedObject>& objects)`, вызываемый из `generateLevel()` сразу после `generateTrees()` (деревья уже в векторе, значит их можно обнаружить). Метод `generateItems()` удаляется — случайного размещения предметов больше нет.

Альтернатива — оставить `generateItems()` для случайного размещения: отклонено, так как все три типа предметов теперь размещаются детерминированно.

### Обнаружение дерева на платформе
Платформа считается занятой деревом, если существует объект `Tree` с `tree.y == block.y` и `block.x <= tree.x <= block.x + block.width`. Это тот же критерий, что используется в существующих тестах (`RealGeneratorPlacesAtMostOneTreePerBlock`), и он напрямую отражает способ расстановки деревьев в `generateTrees()`.

### Нумерация платформ
Платформы берутся как снимок всех `GroundBlock` из `objects` в порядке создания; стартовый блок — индекс 0 (первая платформа). Правила: `(index + 1) % 3 == 0` → патрон; `(index + 1) % 4 == 0` → здоровье; `(index + 1) % 2 == 0` → кристалл. Блок, кратный 12, получает все три предмета (если нет дерева).

### Позиция предмета
Предмет высотой/шириной 50 пикселей ставится на верхнюю грань блока: `y = block.y - 50`. По горизонтали предметы распределяются равномерно по ширине блока в порядке патрон → здоровье → кристалл, без пересечения. Ширина блока ≥ 150 пикселей (минимум 3 тайла), чего достаточно для трёх предметов по 50 пикселей; на блоке с одним предметом он размещается по центру.

### Лимиты
`MAX_AMMO`, `MAX_CRYSTALS` и `MAX_HEARTS` больше не применяются к размещению предметов — правила «каждая третья/четвёртая/пятая» должны выполняться безусловно. Соответствующие счётчики случайного размещения удаляются.

### Декомпозиция под сложность ≤ 2
Размещение выполняется отдельными функциями, каждая не более чем с одной ветвью:
- `isNthPlatform(size_t index, int step)` → `bool` (арифметика без ветвлений);
- `platformHasTree(const std::vector<GeneratedObject>& objects, const GeneratedObject& block)` → цикл с одним `if` внутри (сложность 2);
- `placeAmmunition` / `placeHeart` / `placeCrystal` — без ветвлений;
- `generateGuaranteedAmmo(objects)`, `generateGuaranteedHeart(objects)` и `generateGuaranteedCrystal(objects)` — каждая цикл + один `if` (сложность 2);
- `generatePlatformItems(objects)` — просто вызывает все три (сложность 1).

## Risks / Trade-offs

- [Число блоков уровня может быть меньше 5] → на уровне просто не будет части предметов; правило остаётся корректным (0 совпадений).
- [Дерево может перекрывать предмет визуально, так как проверяется только по координате `y` и границам `x`] → используется тот же критерий, что и в существующих тестах; при необходимости критерий уточняется отдельным изменением.
- [Отказ от лимитов `MAX_AMMO`/`MAX_CRYSTALS`/`MAX_HEARTS` может увеличить число предметов] → размещение ограничено числом блоков, а не бесконтрольно; при переполнении уровней правило пересматривается.
- [На блоке, кратном 12, должны уместиться три предмета по 50 пикселей] → ширина такого блока не меньше 150 пикселей (3 тайла); при нехватке места предметы всё равно не пересекаются за счёт равномерного распределения.
- [Порядок вызова: если `generatePlatformItems` вызвать до `generateTrees`, деревья не будут обнаружены] → вызов жёстко закреплён после `generateTrees` и покрывается тестом.
