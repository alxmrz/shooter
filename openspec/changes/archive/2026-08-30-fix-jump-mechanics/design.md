## Контекст

Механика прыжков реализована в классе `Unit` с системой `jumpCount`, позволяющей до `maxJumps = 2` прыжков. Текущая реализация имеет проблемы:
- Оба прыжка используют разные высоты (375.f для первого, 62.5.f для второго) - значения кажутся перепутанными
- Прыжки можно прервать повторным нажатием кнопки прыжка в воздухе
- Метод `gravitate()` сбрасывает счётчик прыжков при приземлении, что верно

## Цели / Не цели

**Цели:**
- Увеличить высоту первого прыжка (наземный прыжок) для лучшей базы
- Второй прыжок (воздушный) должен быть на ~15% выше первого прыжка
- Предотвратить отмену/прерывание прыжков при повторном нажатии кнопки прыжка в течение одной дуги прыжка
- Обеспечить блокировку третьего прыжка до тех пор, пока игрок не приземлится

**Не цели:**
- Без изменений горизонтального движения во время прыжков
- Без изменений звуковых эффектов прыжков или визуальных эффектов (если не требуется для реализации)
- Без изменений системы прыжков на платформах (платформы вызывают `jump()` напрямую)

## Решения

1. **Расчёт высоты прыжка**: Первый прыжок должен использовать более высокую базовую высоту (375.f пикселей). Второй прыжок должен быть на ~15% выше первого (431.25.f пикселей).

2. **Отслеживание состояния прыжка**: Добавить флаг `jumpInProgress` для отслеживания активной дуги прыжка. Это предотвращает повторный вызов метода прыжка до завершения дуги прыжка (когда игрок начинает падать или приземляется).

3. **Без прерывания прыжка**: Когда `jump()` вызывается во время активной дуги прыжка, он должен игнорироваться, а не сбрасывать или изменять текущий прыжок. Метод должен возвращаться ранее, если `jumpInProgress` равен true.

4. **Поведение счётчика прыжков**: 
   - Первый прыжок (наземный): `jumpCount = 1`, высота = база
   - Второй прыжок (воздушный): `jumpCount = 2`, высота = база * 1.15
   - Сброс `jumpCount = 0` только когда `isGrounded()` возвращает true

5. **Завершение дуги прыжка**: Дуга прыжка "в процессе" с момента завершения `jump()` до начала падения игрока (`falling` становится true). После падения можно начать новый прыжок.

## Риски / Компромиссы

- **Риск**: Изменение высот прыжков может повлиять на предположения о дизайне уровней
  - **Смягчение**: Документировать новые высоты прыжков для дизайнеров уровней
- **Риск**: Предотвращение прерывания прыжков может показаться игрокам ограничительным
  - **Смягчение**: Убедиться, что время и высоты прыжков кажутся отзывчивыми
- **Риск**: Прыжки на платформах (строка 86 в текущем коде) могут взаимодействовать неожиданно
  - **Смягчение**: Тщательно протестировать поведение платформ, может потребоваться сброс `jumpInProgress` при прыжке на платформу

## План миграции

1. Обновить метод `jump()` для отслеживания состояния `jumpInProgress`
2. Изменить расчёт высоты прыжка, используя правильную базу и +15% для второго прыжка
3. Добавить ранний возврат в `jump()`, если `jumpInProgress` равен true
4. Сбросить `jumpInProgress`, когда игрок начинает падать
5. Протестировать все сценарии прыжков: одиночный прыжок, двойной прыжок, попытки прерывания прыжка, прыжки на платформах
