## Контекст

Спрайт стрелка создаётся в `Fabric::createShooter()` (`src/Fabric.cpp:135`) вызовом `createSprite("shooter", x, y)`, который задаёт только текстуру и позицию, но не `textureRect`. В отличие от него, все остальные объекты фабрики (пуля, кристалл, патроны, сердце, земля, спрайт сердца, взрыв) явно задают `textureRect` при создании. У `sf::Sprite` без `textureRect` по умолчанию используются полные границы текстуры, то есть весь атлас.

Кадр для живого стрелка выбирается только в `Shooter::draw()` (`src/objects/units/Shooter.cpp:41`):

```
showNextFrame = elapsedTime >= animationTime   // animationTime = 0.08
if (falling || jumping)        rect = jumpSprites[direction]
else if (moving && showNextFrame)   animateRun()
else if (!moving && !falling && !jumping) rect = noMotionSprites[direction]
```

Для только что созданного движущегося врага `moving == true`, `elapsedTime == 0`, поэтому `showNextFrame == false` и ни одна ветка не выполняется — `textureRect` не назначается, рисуется весь атлас, пока `elapsedTime` не превысит `0.08` (≈5 кадров при 60 FPS).

Ограничения проекта: цикломатическая сложность методов не должна превышать 2; приватные методы определяются сразу после места использования; весь новый код — по TDD; тесты пишутся через DSL без циклов и условий.

См. `proposal.md` — раздел «Зачем» для мотивации.

## Цели / Не цели

**Цели:**
- Спрайт стрелка показывает валидный одиночный кадр с первого кадра отрисовки при любом пути создания (Fabric, Map, LevelGenerator).
- Выбор кадра при движении не зависит от таймера: текущий кадр назначается всегда, таймер управляет только переходом к следующему.
- Логика выбора кадра остаётся тестируемой без графического окна.

**Не цели:**
- Изменение кадров, скорости анимации, размеров спрайтов.
- Изменение механики движения, прыжков, стрельбы, взрыва.
- Изменение других объектов фабрики.

## Решения

1. **Начальный кадр задаётся в `Shooter::setMainSprite()`.** После `Unit::setMainSprite()` установить `mainSprite->setTextureRect(noMotionSprites[direction])`. Это идиоматично (аналогично тому, как фикс вращения задаёт `origin` в `setMainSprite`) и покрывает все пути создания, а не только `Fabric::createShooter`. Альтернатива — задавать кадр в `Fabric::createShooter` — отклонена: покрывает один путь и требует раскрытия приватной карты кадров. Альтернатива — хардкодить прямоугольник в фабрике — отклонена из-за дублирования знания о кадрах.

2. **Выбор кадра выносится в отдельный метод без зависимости от окна.** Ввести метод (например, `refreshSpriteFrame(float dt)`), который для живого стрелка:
   - при `falling || jumping` задаёт кадр прыжка;
   - при `moving` ВСЕГДА задаёт текущий кадр бега `runSprites[direction][currentFrame]`, а переход к следующему кадру выполняет только при `showNextFrame`;
   - при покое задаёт кадр `noMotionSprites[direction]`.
   `draw()` вызывает этот метод, а затем базовую отрисовку. Так поведение тестируется напрямую, без `sf::RenderWindow` (в наборе тестов окно не создаётся). Альтернатива — оставить логику внутри `draw()` и тестировать через окно — отклонена: headless-контекст и лишняя хрупкость.

3. **Разделение «показать кадр» и «продвинуть кадр».** Существующий `animateRun()` смешивает обе задачи. Разделить на: назначение текущего кадра (всегда) и продвижение `currentFrame` с `elapsedTime = 0` (только по таймеру). Так устраняется латентный разрыв, когда при `moving && !showNextFrame` кадр вообще не назначался.

4. **Сложность ≤ 2.** `refreshSpriteFrame()` и его ветки декомпозировать на маленькие методы (`refreshMovingFrame()`, `refreshIdleFrame()`, `refreshJumpFrame()`, `advanceRunFrame()`); каждый приватный метод объявлять сразу после вызывающего, согласно конвенции проекта.

5. **Тестируемость (TDD).** Тесты через `GameObjectsFixture` (`tests/GameObjectsTestFixture.h`), который даёт живой `GameObjects` и спрайт с текстурой, и через `Shooter::getDrawForm()` + `dynamic_cast<sf::Sprite*>`, как в `tests/Shooter_test.cpp`:
   - после `setMainSprite()` прямоугольник спрайта равен кадру покоя для направления (не полной текстуре);
   - после движения и `refreshSpriteFrame(0)` прямоугольник равен первому кадру бега для направления;
   - после движения и `refreshSpriteFrame(animationTime)` прямоугольник равен следующему кадру бега;
   - в покое повторный вызов сохраняет кадр покоя.
   Ассерты вынести в DSL-функции без циклов и условий.

## Риски / Компромиссы

- **Риск:** раскрытие `refreshSpriteFrame()` в публичный интерфейс расширяет API класса. → **Смягчение:** метод отражает осмысленную операцию (обновление кадра по состоянию) и нужен для тестируемости; альтернатива с окном в тестах ненадёжна.
- **Риск:** начальный кадр (покой) может не совпасть с фактическим состоянием (например, враг сразу падает). → **Смягчение:** `refreshSpriteFrame()` на первой же отрисовке перезапишет кадр по реальному состоянию; начальный кадр — лишь гарантия отсутствия полного атласа.
- **Риск:** существующие тесты `tests/Shooter_test.cpp` проверяют `origin`/позицию и могут быть затронуты. → **Смягчение:** изменение касается только `textureRect`, `origin` и позиции не трогаем; прогнать весь набор `make test`.
- **Риск:** размер кадра может не совпадать с `getWidth()/getHeight()`. → Не влияет: `textureRect` задаётся явными координатами атласа, как и раньше.

## План миграции

1. Добавить падающие тесты в новый/существующий тестовый файл через `GameObjectsFixture` (раздел 1 задач).
2. Задать начальный `textureRect` в `Shooter::setMainSprite()`.
3. Вынести выбор кадра в `refreshSpriteFrame(dt)` и разделить показ/продвижение кадра; вызвать из `draw()`.
4. Собрать и прогнать `make test`, затем `make` и визуально проверить отсутствие вспышки атласа.
