## Context

Текущая система уровней основана на ручном создании XML-файлов в Tiled. Существует класс `Map`, который загружает уровни из XML и создает объекты через `Fabric`. Параметры прыжка игрока известны: наземный прыжок 50px, воздушный 60px (итого 110px максимальная высота двойного прыжка).

## Goals / Non-Goals

**Goals:**
- Создать генератор уровней, который программно создает уровни 3000x3000 пикселей
- Обеспечить автоматическое размещение платформ с учетом ограничений прыжка
- Случайно размещать предметы (кристаллы, здоровье, патроны) и врагов
- Интегрировать генератор с существующей системой Map

**Non-Goals:**
- Изменение механики прыжка или физики игры
- Создание пользовательского интерфейса для настройки генерации
- Сохранение сгенерированных уровней на диск (генерация в реальном времени)
- Сложные алгоритмы генерации (Procedural Content Generation)

## Decisions

### 1. Архитектура генератора
**Решение:** Создать отдельный класс `LevelGenerator`, который будет генерировать уровень и возвращать его в виде структуры данных, совместимой с `Map`.

**Альтернативы:**
- Модифицировать `Map` для добавления логики генерации → отвергнуто, так как нарушает принцип единственной ответственности
- Создать наследника `Map` → отвергнуто, так как генерация не является вариацией загрузки

**Почему:** Выделение генератора в отдельный класс позволяет разделить ответственность и упростить тестирование.

### 2. Алгоритм размещения платформ
**Решение:** Использовать вертикальный扫描 с фиксированным шагом, с случайным горизонтальным смещением.

**Алгоритм:**
1. Начать с нижней границы (y=2950) - создать ground
2. Двигаться вверх с шагом 50-100 пикселей (случайно)
3. На каждом уровне размещать 1-3 платформы с случайным горизонтальным позиционированием
4. Проверять, чтобы расстояние между платформами по вертикали не превышало 110 пикселей

**Альтернативы:**
- Случайное размещение без алгоритма → отвергнуто, так как может создать непроходимые участки
- Генерация на основе шаблонов → отвергнуто для простоты реализации

### 3. Размещение предметов
**Решение:** Размещать предметы на существующих платформах и в случайных позициях между ними.

**Алгоритм:**
1. Для каждой платформы с вероятностью 30% разместить 1-2 предмета
2. В промежутках между платформами с вероятностью 10% разместить предмет в воздухе
3. Ограничить максимальное количество предметов одного типа на уровне

### 4. Размещение врагов
**Решение:** Размещать врагов в позициях, гарантированно находящихся за пределами видимости камеры.

**Алгоритм:**
1. Определить размер видимой области камеры (примерно 800x600 пикселей)
2. Размещать врагов только в позициях, которые не пересекаются с видимой областью
3. Ограничить максимальное количество врагов до 10
4. Распределять врагов по всему уровню, избегая скоплений

### 5. Интеграция с Map
**Решение:** Добавить метод `generateLevel` в `LevelGenerator`, который будет вызывать `Map::generateLevel` с сгенерированными данными.

**Реализация:**
1. `LevelGenerator` создает вектор объектов с типами и позициями
2. Преобразует данные в формат, понятный `Map`
3. Вызывает `Map::generateLevel` для создания объектов в игре

## Risks / Trade-offs

**Риск:** Генерация может создавать непроходимые уровни.
**Митигация:** Тестирование алгоритма генерации платформ и проверка доступности всех участков уровня.

**Риск:** Случайное размещение предметов может быть несбалансированным.
**Митигация:** Ограничения количества предметов и их распределение по всему уровню.

**Риск:** Производительность генерации в реальном времени.
**Митигация:** Простой алгоритм генерации, не требующий сложных вычислений.

**Trade-off:** Простота реализации vs разнообразие уровней.
**Решение:** Начать с простого алгоритма, в будущем усложнить при необходимости.
