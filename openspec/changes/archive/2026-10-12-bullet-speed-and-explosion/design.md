## Context

См. `proposal.md` — раздел «Зачем». Текущее состояние, важное для подхода:

- `Bullet::update()` (`src/objects/interactive/Bullet.cpp:32`) вызывает `move(10.f, 0.f)`; при `false` вызывает `destroy()`, который убирает объект из `go->all`.
- `Bullet::move()` возвращает `false` в трёх случаях: достижение `endPosition` (точное сравнение), столкновение с юнитом (`collidePlayableAfterMove`), столкновение с границей/препятствием (`collideObjectAfterMove`).
- Звук взрыва сейчас играет внутри `collidePlayableAfterMove()` (`Bullet.cpp:86`) только при попадании в юнита; спрайта взрыва у пули нет.
- `update(Event)` не получает `dt`, объекты обновляются с фиксированным шагом (60 FPS, `Application::run`). Движение пули — тоже фиксированный шаг за кадр.
- Анимация взрыва уже есть у стрелка: кадры `oneshot.png` (`Shooter::explosionSprites`), продвижение по `dt` внутри `Shooter::draw()`.
- `Fabric::createBullet()` (`src/Fabric.cpp:36`) уже передаёт пуле звук взрыва через `setExplosionSound()`; текстура и звук `explosion` уже загружены в `Resources`.
- Тесты не создают `sf::RenderWindow` и не инстанцируют `Fabric`; фикстура `GameObjectsFixture` даёт живой `GameObjects` с пустыми `all`/`borders` и спрайты с фиктивной текстурой.

Ограничения проекта: цикломатическая сложность новых методов ≤ 2; приватные методы объявляются сразу после вызывающего; весь новый код — по TDD; тесты пишутся через DSL без циклов и условий в теле теста.

## Goals / Non-Goals

**Goals:**
- Уменьшить шаг перемещения пули на 20% (10 → 8) без изменения механики урона и направления.
- Во всех случаях исчезновения пули показать анимированный спрайт взрыва и один раз проиграть звук.
- Сохранить максимальную дальность полёта пули (≈500 px) при новом шаге.
- Оставить поведение проверяемым в headless-тестах (без окна и без `Fabric`).

**Non-Goals:**
- Изменение урона, здоровья, количества патронов, наведения и скорости стрельбы.
- Введение нового класса-эффекта или изменение жизненного цикла объектов в `GameObjects`.
- Изменение существующей анимации взрыва стрелка.

## Decisions

1. **Шаг перемещения — именованная константа `8.f` в `Bullet`.** Значение на 20% меньше прежних 10. Альтернатива — оставить магическое число в `update()` — отклонена: константа документирует связь с требованием и упрощает тест.

2. **Максимальная дальность сохраняется сменой точного сравнения на пороговое.** При шаге 8 позиция `startX + 500` не достигается точно (500 не делится на 8), поэтому прежнее равенство `endPosition[0] == this->x + x` перестаёт срабатывать и пуля летит до границы. Ввести `isEndPositionReached(nextX)` с направленным порогом (`left`: `nextX <= endPosition[0]`, иначе `nextX >= endPosition[0]`). Так дальность остаётся ≈500 px, несмотря на новый шаг. Альтернатива — оставить равенство и позволить пуле лететь до границы — отклонена: это меняет наблюдаемое поведение дальности.

3. **Взрыв реализуется «переходом» самой пули в анимацию взрыва, а не отдельным объектом.** Пуля при исчезновении не удаляется сразу, а переключается в состояние `exploding`: прекращает двигаться, показывает кадры `oneshot.png` и по завершении анимации вызывает `destroy()`. Причины:
   - не нужен новый класс и фабричный метод, которые пришлось бы связывать с `Fabric` (в тестах `Fabric` не инстанцируется, `go->fabric == nullptr`);
   - поведение наблюдаемо идентично отдельному объекту-эффекту («в позиции исчезновения появляется спрайт взрыва»), но не затрагивает жизненный цикл `GameObjects`;
   - повторяет уже принятый в проекте приём для взрыва стрелка (объект владеет спрайтом взрыва, установленным из `Fabric`).
   Альтернатива — отдельный `Explosion`, создаваемый `Fabric` — отклонена из-за связности и сложностей с удалением объекта во время итерации `go->all`.

4. **Анимация продвигается в `update()`, а не в `draw()`.** `update()` не получает `dt`, но вызывается с фиксированным шагом; анимация продвигается по счётчику кадров (`explosionTick` / `explosionFrameDelay`), а не по времени. Это согласуется с фиксированным шагом движения пули и делает анимацию и удаление проверяемыми без окна: тест многократно вызывает `update()` и наблюдает смену кадров и удаление. Альтернатива — продвигать в `draw(dt)` (как у стрелка) — отклонена: `draw()` требует `Window`, тесты headless, и удаление объекта во время цикла отрисовки `GameObjects::draw` нежелательно.

5. **Единственное воспроизведение звука.** `collidePlayableAfterMove()` больше не вызывает `explosionSound->play()`; воспроизведение переносится в `startExplosion()`, который идемпотентен (повторный вызов при `exploding == true` ничего не делает). Так звук звучит ровно один раз за исчезновение, что и требует спецификация. Плей выполняется с проверкой указателя на `nullptr` (в тестах звук не задаётся).

6. **`draw()` выбирает спрайт по состоянию.** Пока пуля летит — рисуется `mainSprite` (базовая отрисовка `CObject`); при `exploding` — `explosionSprite`. Прямое управление кадрами остаётся в `update()`, `draw()` только отражает состояние.

7. **Кадры взрыва переиспользуются.** Чтобы не дублировать прямоугольники `oneshot.png` между `Shooter` и `Bullet`, вынести их в общий источник (например, свободная функция `explosionFrames()` в `src/objects/interactive/ExplosionFrames.h`), которую используют оба класса. Значения не меняются.

8. **Сложность ≤ 2.** Разложить `update()` на `updateFlight()` и `updateExplosion()`, а продвижение кадров — на `shouldAdvanceExplosion()` / `advanceExplosion()` / `applyExplosionFrame()`. Каждый метод содержит не более одного ветвления; приватные методы объявляются сразу после вызывающего.

9. **Тестируемость (TDD).** Тесты через `GameObjectsFixture`:
   - скорость: после `update()` координата сдвигается на 8 (а не на 10);
   - запуск взрыва: при столкновении с препятствием (граница в `go->borders`), с юнитом и при достижении максимальной дальности `isExploding()` становится `true`;
   - анимация: вызовы `update()` последовательно меняют кадр;
   - завершение: после проигрывания всех кадров пуля исчезает из `go->all`;
   - однократность перехода: повторные `update()` не перезапускают анимацию.
   Ассерты и «прогон N обновлений» вынести в DSL-функции без циклов/условий в теле тестов.

## Risks / Trade-offs

- **Риск:** смена сравнения дальности на пороговое может остановить пулю на пару пикселей раньше/позже 500 px. → **Смягчение:** поведение остаётся «примерно максимальная дальность», что не отличимо для игрока; тест фиксирует факт остановки по дальности, а не точную координату.
- **Риск:** объект-пуля во время анимации взрыва остаётся в `go->all` с коллайдером 10×10. → **Смягчение:** пуля не является `Unit`, другие системы её не обрабатывают; влияние отсутствует.
- **Риск:** вынос кадров в общий источник затрагивает `Shooter`. → **Смягчение:** значения прямоугольников не меняются, поведение стрелка не меняется; прогоняется весь набор `make test`.
- **Риск:** двойное воспроизведение звука, если старое `play()` останется в `collidePlayableAfterMove`. → **Смягчение:** явная задача на удаление старого вызова и тест на однократность перехода.
- **Риск:** анимация, привязанная к числу обновлений, зависит от фиксированного шага 60 FPS. → **Смягчение:** это уже действующее допущение для движения пули; при смене шага подстроить `explosionFrameDelay`.

## Migration Plan

1. Добавить падающие тесты (раздел 1 задач) через `GameObjectsFixture`.
2. Ввести пороговую проверку дальности и константу скорости; проверить тест скорости.
3. Добавить состояние взрыва, спрайт и анимацию; убрать старый `play()`; проверить тесты взрыва.
4. Вынести общие кадры взрыва, задействовать в `Shooter` и `Bullet`.
5. `make test`, затем `make` и визуально проверить скорость, взрыв и звук.
