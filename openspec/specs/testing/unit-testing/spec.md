## Purpose

Инфраструктура модульного тестирования для проекта шутера — позволяет писать и запускать изолированные тесты для всех компонентов, обеспечивая автоматическую проверку корректности кода и выявление регрессий.

## Requirements

### Requirement: Google Test интегрируется через CMake FetchContent

Проект SHALL использовать Google Test как фреймворк для модульных тестов. Библиотека SHALL скачиваться и собираться автоматически через CMake `FetchContent` без необходимости ручной установки.

#### Scenario: Автоматическое скачивание Google Test

- **WHEN** выполняется首次 конфигурация CMake (или Google Test отсутствует в сборке)
- **THEN** CMake SHALL автоматически скачать Google Test из официального репозитория и собрать его как часть проекта

#### Scenario: Google Test доступен в тестах

- **WHEN** компилируется тестовый файл, который включает `<gtest/gtest.h>`
- **THEN** заголовочный файл SHALL быть доступен без дополнительных флагов компиляции (настроено через CMake target)

### Requirement: Основной проект выделяется в библиотеку

Объектные файлы основного проекта SHALL собираться в статическую библиотеку `shooter_lib`, чтобы тесты могли подключать исходный код без повторной компиляции.

#### Scenario: Библиотека shooter_lib собирается успешно

- **WHEN** выполняется `cmake --build build`
- **THEN** в директории `build/` SHALL появиться файл библиотеки `libshooter_lib.a` (или аналогичный на платформе)

#### Scenario: Основной исполняемый файл линкуется с библиотекой

- **WHEN** выполняется сборка основного исполняемого файла `run`
- **THEN** он SHALL линковаться с `shooter_lib` и содержать тот же функционал, что и до реорганизации

### Requirement: Тесты собираются отдельной целью CMake

Тесты SHALL собираться как отдельная цель CMake `tests`, не влияя на основную сборку.

#### Scenario: Цель tests определена в CMake

- **WHEN** выполняется `cmake --build build --target tests`
- **THEN** SHALL собираться исполняемый файл тестов

#### Scenario: Запуск тестов

- **WHEN** выполняется собранный исполняемый файл тестов
- **THEN** Google Test SHALL выполнить все тесты и вывести результаты (количество пройденных/проваленных)

### Requirement: Структура тестовых файлов

Тестовые файлы SHALL располагаться в директории `tests/` с поддиректориями, повторяющими структуру `src/`.

#### Scenario: Директория tests создана

- **WHEN** проект проверяется на наличие тестовой инфраструктуры
- **THEN** SHALL существовать директория `tests/` с файлами `*_test.cpp`

### Requirement: Набор модульных тестов

Проект SHALL содержать модульные тесты для ключевых компонентов, проверяющие их основную функциональность.

#### Scenario: Тесты GameState

- **WHEN** запускаются тесты
- **THEN** SHALL выполняться тесты для `GameState` (инициализация, обновление состояния, обработка гравитации)

#### Scenario: Тесты GameObjects

- **WHEN** запускаются тесты
- **THEN** SHALL выполняться тесты для `GameObjects` (добавление/удаление объектов, перебор объектов)

#### Scenario: Тесты Fabric

- **WHEN** запускаются тесты
- **THEN** SHALL выполняться тесты для `Fabric` (создание различных типов объектов)

#### Scenario: Тесты EventHandler

- **WHEN** запускаются тесты
- **THEN** SHALL выполняться тесты для `EventHandler` (регистрация и обработка событий)

### Requirement: Основной Makefile не затрагивается

Текущий процесс сборки через `make` SHALL продолжать работать без изменений, обеспечивая обратную совместимость.

#### Scenario: make собирает основной проект

- **WHEN** выполняется `make`
- **THEN** SHALL собираться исполняемый файл `run` без необходимости конфигурации CMake
